# proxy-rs — руководство пользователя и разработчика

`proxy-rs` — кроссплатформенная консольная программа на Rust для сбора прокси из подписок и файлов, разбора и дедупликации ссылок, определения страны, проверки TCP-доступности и измерения скорости через Xray. При необходимости программа создаёт конфигурацию Clash/mihomo.

Это руководство описывает поведение текущей версии приложения. Таблица параметров сверена с выводом `cargo run -- --help`, а детали pipeline и файлов — с реализацией и настройками проекта.

## Возможности и ограничения

- Подписки загружаются параллельно; текстовые ответы могут быть обычным текстом или Base64-кодированной подпиской.
- Разбираются протоколы `vless`, `vmess`, `trojan` и `ss` (Shadowsocks). Извлечение также распознаёт некоторые другие схемы, но распознавание ссылки не означает поддержку протокола: неподдерживаемые записи учитываются отдельно и не проверяются.
- TCP-проверка — быстрый предварительный фильтр. Она проверяет TCP-соединение с адресом прокси и сама по себе не подтверждает работоспособность прокси-протокола.
- Скорость измеряется через локально запущенное ядро Xray и SOCKS-входы, созданные для кандидатов.
- Clash/mihomo YAML строится отдельной библиотекой `proxy-clash` из прокси, прошедших порог скорости.

## Требования и сборка

Для сборки нужен стабильный Rust toolchain с Cargo. Проверочные CI-сборки выполняются на Ubuntu, macOS и Windows. `reqwest` собран с `rustls-tls`, поэтому для сборки не требуется системный OpenSSL.

```sh
git clone <адрес-репозитория>
cd proxyRepoChecker-rs
cargo build --release
```

Бинарник создаётся в `target/release/`: `proxy-rs` на Unix-подобных системах и `proxy-rs.exe` на Windows. При запуске по умолчанию рядом с исполняемым файлом размещаются или загружаются `geoip.dat` и ядро Xray (`xray` либо `xray.exe`). Для полной работы с сетевыми источниками, GeoIP и Xray нужен доступ в сеть. Режим `--no-speed` не использует Xray; `--no-geoip` отключает загрузку GeoIP.

Сборку можно проверить без запуска приложения:

```sh
cargo check --workspace
cargo build --workspace --release
```

### Скрипты сборки и cross-compilation

На macOS/Linux запускайте Bash-скрипт, на Windows — BAT из `cmd.exe`. Без аргументов собирается текущая платформа; доступны `linux`, `macos`, `windows` и `all`, архитектуры — `x86_64` и `aarch64`:

```sh
scripts/build.sh                         # текущая платформа
scripts/build.sh linux --arch aarch64 --install-target
scripts/build.sh all --arch x86_64
```

```bat
scripts\build.bat windows --arch x86_64 --install-target
scripts\build.bat all --arch aarch64 --install-target
```

`--install-target` устанавливает Rust target через rustup, но не linker или SDK. Для Windows GNU нужен совместимый MinGW linker, для Windows ARM64 — MSVC toolchain, для macOS — Apple SDK/toolchain; cross-build может потребовать настройки linker в Cargo. Нативный результат находится в `target/release/`, cross-build — в `target/<rust-target>/release/`. Скрипты продолжают сборку остальных целей после ошибки, но завершаются с ненулевым кодом, если хотя бы одна цель не собрана.

## Запуск

Показать актуальную справку и версию:

```sh
cargo run -- --help
cargo run -- --version
```

Быстрый проверочный запуск по первым 200 элементам набора 3:

```sh
cargo run -- --set 3 -n 200 --shuffle
```

Проверка одной подписки и настройка минимальной скорости:

```sh
proxy-rs --url 'https://example.org/subscription' --min-kb 500 --limit 100
```

В Unix shell замените `proxy-rs` на `./target/release/proxy-rs`, если бинарник ещё не установлен в `PATH`; в PowerShell используйте `target\release\proxy-rs.exe`.

Тестовый запуск всё равно обращается к указанным сетевым источникам и может загружать GeoIP и Xray. Не запускайте большой набор (`--set all`) без необходимости: он не является локальной проверкой.

## Источники и форматы входных данных

### `sources.json`

По умолчанию программа ищет `sources.json`. В репозитории исходный файл находится в `bin/sources.json`; `build.rs` копирует его в каталог профиля Cargo при сборке. Для другого расположения используйте `--sources PATH`.

Файл должен содержать JSON-объект, ключи которого — идентификаторы наборов, а значения — массивы строк с URL подписок:

```json
{
  "1": ["https://example.org/subscription-a"],
  "2": ["https://example.org/subscription-b"],
  "3": ["https://example.org/subscription-c"]
}
```

`--set 3` выбирает один указанный набор (по умолчанию — `3`); `--set all` читает все наборы из объекта. Запрошенный ключ должен существовать и иметь тип массива, иначе программа сообщает об ошибке. Элементы массива, которые не являются строками, пропускаются. URL, повторившиеся в объединённом списке наборов, `--url` и файла ссылок, дедуплицируются с сохранением первого появления.

Если файла `sources.json` нет, запуск всё ещё возможен при наличии `--url` или `--file`. Если нет ни файла источников, ни этих аргументов, программа завершится с ошибкой.

### Файл `--file`

`-f/--file` принимает текстовый файл, по одной записи на строку:

- пустые строки и строки, начинающиеся после обрезки пробелов с `#`, игнорируются;
- строки, начинающиеся с `http://` или `https://` (без учёта регистра), считаются URL подписок и загружаются;
- остальные строки с `://` считаются готовыми ссылками прокси;
- другие строки игнорируются.

В одном `--file` можно смешивать URL подписок и готовые ссылки. Повторяйте `-u/--url`, чтобы добавить несколько URL подписок.

### Поддерживаемые ссылки

Входные тексты обрабатываются как содержимое подписки: программа извлекает из текста ссылки известных схем. Поддерживаются `vless://`, `vmess://`, `trojan://`, `ss://`. Для VMess принимаются URI-форма и форма с Base64-кодированным JSON. Схемы вроде `ssr://`, `hysteria2://`/`hy2://`, `tuic://` и `anytls://` распознаются как неподдерживаемые, а не проверяются.

## Этапы обработки

Обычный pipeline выглядит так:

```text
источники → загрузка → извлечение ссылок → разбор и дедупликация
          → ограничение/перемешивание → GeoIP → TCP-фильтр
          → Xray и замер скорости → alive/good/dead → Clash YAML (опционально)
```

1. **Сбор источников.** `sources.json`, дополнительные URL `--url` и строки из `--file` разделяются на URL подписок и прямые ссылки прокси.
2. **Загрузка подписок.** HTTP-источники запрашиваются параллельно с ограничением `--fetch-concurrency` и таймаутом `--fetch-timeout`. Неудачные источники перечисляются в сводке; если не загрузился ни один источник и нет прямых ссылок, запуск завершается ошибкой.
3. **Извлечение и разбор.** Из загруженного текста извлекаются proxy URI; прямые ссылки из файла добавляются к ним. Разбор классифицирует записи как валидные, дубли, некорректные или неподдерживаемые. Уникальность определяется ключом прокси, а не только исходной строкой.
4. **Перемешивание и лимит.** Если задан `--shuffle`, порядок меняется до применения `--limit`. Лимит применяется к уникальным разобранным прокси до GeoIP и проверок.
5. **GeoIP.** Если не задан `--no-geoip`, определяется страна и формируется отображаемое имя вида `[XX] - NNN`. При отключённом GeoIP отображаемое имя берётся из имени исходной ссылки.
6. **TCP ping.** Если не задан `--no-tcp-ping`, выполняются параллельные TCP-пробы с таймаутом и числом попыток. `--tcp-max-ms` ограничивает RTT внутри TCP-фильтра; `--max-ping` дополнительно отбрасывает результаты с RTT выше заданного значения. Прокси, не прошедшие эти ограничения, попадают в список dead.
7. **Скорость.** Если не задан `--no-speed`, кандидаты запускаются через Xray пакетами `--batch`, с параллелизмом `--batch-workers`; отдельные измерения ограничены `--speed-threads`. Прокси проходят порог, если измеренная скорость не ниже `--min-kb`.
8. **Запись итогов.** `alive` сортируется по TCP ping; `good` — по скорости. В `dead`, если путь указан через `--dead`, добавляются URL кандидатов, отброшенных на TCP/`--max-ping` или проверке Xray/скорости.
9. **Clash/mihomo (опционально).** При `--clash` YAML строится из прошедших порог скорости прокси. Если таких прокси нет, генерация пропускается.

### Значение `alive`, `good` и `dead`

- **`alive.txt`** — итоговый список живых для выбранного режима. При обычном запуске это прокси, прошедшие Xray-замер и порог `--min-kb`; при `--no-speed` — кандидаты, оставшиеся после TCP-фильтра. При `--no-tcp-ping` TCP-фильтр пропускается, поэтому в режиме `--no-speed` список включает все разобранные кандидаты (с учётом `--max-ping`, если он задан; без измеренного ping такие кандидаты не проходят положительный `--max-ping`).
- **`good.txt`** — только прокси, прошедшие проверку скорости. При `--no-speed` этот файл не создаётся и не обновляется. Во время Xray-проверки файл обновляется по завершённым батчам, затем записывается окончательный отсортированный результат.
- **`dead.txt`** — необязательный список исходных URL прокси, не прошедших TCP-фильтр, `--max-ping` или обработку Xray. Он создаётся только при переданном `--dead PATH`; это не отдельная классификация протокола.

HTTPS-сертификаты источников проверяются по умолчанию. Ответ ограничен 16 MiB на источник (`--max-source-bytes`); повтор выполняется дважды после начальной попытки (`--fetch-retries`, допустимо `0..=8`). Каталог `.proxy_cache` по умолчанию хранит успешные ответы и HTTP validators `ETag`/`Last-Modified`: валидатор уменьшает повторную загрузку, а последняя успешная копия используется при временной ошибке. Кэш можно отключить через `--no-fetch-cache`. `--insecure-source-tls` явно отключает проверку TLS-сертификата.

`--source-report source-quality.json` записывает JSON со статусом и счётчиками источников: загружено, валидно, дубли, TCP-живые и прошли проверку скорости. В URL скрываются учётные данные, query, fragment и непустой путь; тело ответа и текст сетевой ошибки в отчёт не включаются.

Чтобы сохранять завершённые этапы, задайте `--checkpoint run.checkpoint`. После прерывания продолжите так:

```sh
proxy-rs --resume --checkpoint run.checkpoint
```

`--resume` требует `--checkpoint FILE`. Checkpoint содержит ссылки и результаты прокси, поэтому храните его как приватный файл; для продолжения используйте совместимые параметры запуска.

Таблица соответствует `cargo run -- --help`. Числовые ограничения, которые help не отображает, приведены по валидатору CLI.

| `-V`, `--version` | — | Показать версию. |
| `--set SET` | `3` | Набор из `sources.json`: ключ набора, например `1`, `2`, `3`, либо `all`. |
| `--sources SOURCES` | `sources.json` | Путь к JSON-файлу наборов. |
| `-f`, `--file FILE` | не задан | Файл строк с URL подписок и/или прямыми ссылками прокси. |
| `-u`, `--url URL` | пусто | Дополнительный URL подписки; аргумент можно повторять. |
| `--fetch-concurrency N` | `32` | Параллельные загрузки; `1..=4096`. |
| `--fetch-timeout SEC` | `15` | Таймаут источника в секундах; `1..=3600`. |
| `--fetch-retries N` | `2` | Повторы после временных ошибок; `0..=8`. |
| `--max-source-bytes N` | `16777216` (16 MiB) | Максимальный размер ответа одного источника; `1024..=1073741824`. |
| `--insecure-source-tls` | выключен | Отключить проверку сертификатов HTTPS-источников; по умолчанию проверка включена. |
| `--fetch-cache-dir DIR` | `.proxy_cache` | Каталог кэша успешных подписок и HTTP validators. |
| `--no-fetch-cache` | выключен | Отключить кэш и conditional requests. |
| `--resume` | выключен | Продолжить из checkpoint; требует `--checkpoint FILE`. |
| `--protocol PROTOCOL` | не задан | Оставить только указанные протоколы; флаг можно повторять или задавать значения через запятую. Сравнение без учёта регистра. |
| `--country COUNTRY` | не задан | Оставить только указанные ISO-коды стран или GeoIP-теги; флаг можно повторять или задавать значения через запятую. Сравнение без учёта регистра. |

| `-o`, `--output FILE` | `alive.txt` | Файл итогового списка alive. |
| `--good-output FILE` | `good.txt` | Файл прошедших порог скорости; при `--no-speed` не обновляется. |
| `--dead FILE` | не задан | Путь для списка отброшенных ссылок; без флага файл не записывается. |
| `-n`, `--limit N` | не задан | Ограничить число уникальных разобранных прокси; `N > 0`. Применяется после `--shuffle`, до проверок. |
| `-s`, `--shuffle` | выключен | Перемешать разобранные прокси до применения лимита. |
| `--raw-output FILE` | `raw.txt` | Тексты успешно загруженных подписок. |

| `--json-output FILE` | не задан | Записать итоговые alive-прокси в JSON-массив со сводными полями `protocol`, `server`, `port`, `name`, `country`, `display`, `ping_ms`, `speed_kbs`. URI, пароль, UUID и настройки подключения не включаются. |

| `--clash-no-categories` | выключен | Не создавать группы категорий Telegram, AI, YouTube и Игры; также меняются правила, направляющие категории. |
| `--core CORE` | `xray` или `xray.exe` | Путь к бинарнику Xray; имя зависит от ОС. |
| `--workdir WORKDIR` | `.proxy_runtime` | Рабочий каталог временных конфигов Xray. |
| `--batch N` | `100` | Число прокси в одном батче Xray; `1..=10000`. |
| `--lport PORT` | `10000` | Базовый локальный SOCKS-порт; `1024..=65000`. |
| `--batch-workers N` | `8` | Число параллельно обрабатываемых батчей; `1..=1024`. |
| `--core-start-timeout SEC` | `8` | Ожидание запуска Xray в секундах; `1..=3600`. |
| `--xray-url URL` | URL релиза XTLS/Xray-core для текущей ОС | Переопределить URL загрузки ядра. |
| `--no-xray-download` | выключен | Запретить автозагрузку Xray; ошибка, если пригодного ядра нет. |
| `--no-tcp-ping` | выключен | Пропустить TCP ping-префильтр. |
| `--tcp-timeout SEC` | `3` | Таймаут TCP-соединения; `0.1..=3600`. |
| `--tcp-concurrency N` | `1000` | Параллельные TCP-пробы; `1..=65536`. |
| `--tcp-retries N` | `1` | Число попыток на адрес; `1..=100`. |
| `--tcp-max-ms MS` | `0` | Максимальный RTT внутри TCP-префильтра; `0` отключает этот предел. |
| `--max-ping MS` | `0` | Дополнительный предел TCP RTT после префильтра; `0` выключает. |
| `--no-speed` | выключен | Пропустить замер скорости через Xray. |
| `--speed-url URL` | не задан | Приоритетный URL для теста скорости; при пустом значении используются встроенные цели. |
| `--speed-timeout SEC` | `6` | Таймаут загрузки при измерении; `1..=3600`. |
| `--speed-connect-timeout SEC` | `3` | Таймаут установления соединения при измерении; `1..=3600`. |
| `--speed-max-mb MB` | `5` | Максимальный объём загрузки на замер; `0.5..=1024`. |
| `--min-kb KB/S` | `100` | Минимальная скорость для попадания в good; валидатор принимает `0..=1 000 000 000`. |
| `--speed-threads N` | `16` | Параллельные измерения скорости; `1..=4096`. |
| `--no-geoip` | выключен | Отключить GeoIP и страновое переименование. |
| `--geoip-db FILE` | рядом с исполняемым файлом: `geoip.dat` | Путь к базе GeoIP. |
| `--geoip-url URL` | `https://raw.githubusercontent.com/runetfreedom/russia-v2ray-rules-dat/release/geoip.dat` | URL загрузки базы GeoIP. |

Времена и объём скорости должны быть конечными числами; `NaN` и бесконечность отвергаются. Для диапазонов с включёнными концами допустимы граничные значения.

Например, чтобы получить только новые VLESS/VMess-прокси из США и Германии, сравнить их с текущим `alive.txt` и записать итог в JSON:

```sh
proxy-rs --url 'https://example.org/sub' --protocol vless,vmess \
  --country US,DE --only-new --json-output new-proxies.json
```

## Файлы, пути и семантика результатов

| Файл / каталог | Когда используется | Содержимое |
|---|---|---|
| `bin/sources.json` | Исходный набор источников в репозитории | JSON-объект с массивами URL по ключам наборов. |
| `raw.txt` | После успешной загрузки хотя бы одной подписки | Тексты ответов источников; задаётся через `--raw-output`. |
| `parsed.txt` | После парсинга, затем после GeoIP | Сначала исходные ссылки прокси, затем ссылки с отображаемыми именами; задаётся через `--parsed-output`. |
| `alive.txt` | После успешного TCP-фильтра или завершённой проверки скорости | Итоговый список alive; сортируется по TCP ping, если значения ping доступны. Если TCP-фильтр не оставил кандидатов, файл не создаётся и не обновляется (старый файл может сохраниться); путь меняется `--output`. |
| `good.txt` | По мере завершения батчей проверки скорости | Прокси, прошедшие `--min-kb`, сортированные по скорости; при `--no-speed` или раннем выходе до проверки скорости файл не обновляется. Путь меняется `--good-output`. |
| путь `--dead` | Только если флаг задан | URL прокси, отброшенных фильтрами или проверкой Xray. |
| `clash.yaml` | Только при `--clash` и непустом good | YAML для Clash/mihomo; имя или путь задаётся флагом. |
| `geoip.dat` | При включённом GeoIP | Загруженная бинарная база; по умолчанию рядом с исполняемым файлом. |
| `xray` / `xray.exe` | При включённой проверке скорости | Исполняемое ядро; по умолчанию рядом с бинарником приложения. |
| `.proxy_runtime/` | При проверке скорости | Временные конфигурации батчей Xray; путь задаётся `--workdir`. |

Относительные пути для выходных файлов разрешаются относительно текущего рабочего каталога процесса. Для `--core` программа сначала использует существующий заданный путь; поиск значения по умолчанию также проверяет расположение рядом с приложением и каталог `bin/` проекта. GeoIP по умолчанию хранится рядом с исполняемым файлом. Записи текстовых выходов выполняются атомарно через временный файл и замену целевого файла.

Формат строк `alive`, `good` и `parsed` — URI прокси; при наличии отображаемого имени оно добавляется как fragment `#имя`. В `raw` сохраняется ответ сервера подписки, а в `dead` — базовая ссылка прокси без имени.

## Xray и проверка скорости

Если подходящего `--core` нет, приложение пытается загрузить архив ядра Xray с релизов XTLS/Xray-core, если не передан `--no-xray-download`. Архив обрабатывается приложением; исполняемый файл размещается по пути ядра. Для автоматической загрузки предусмотрены имена релизов для Windows, Linux и macOS на `x86_64` и `aarch64`:

| ОС | x86_64 | aarch64 |
|---|---|---|
| Windows | `Xray-windows-64.zip` | `Xray-windows-arm64-v8a.zip` |
| Linux | `Xray-linux-64.zip` | `Xray-linux-arm64-v8a.zip` |
| macOS | `Xray-macos-64.zip` | `Xray-macos-arm64-v8a.zip` |

`--xray-url` позволяет задать другой архив. `--no-xray-download` не отключает проверку: он требует, чтобы рабочее ядро уже существовало. При неверном или неподдерживаемом бинарнике запуск проверки завершается ошибкой.

Xray конфигурируется батчами: число записей в батче задаёт `--batch`, одновременные батчи — `--batch-workers`, параллельные запросы замера — `--speed-threads`. Для каждого кандидата измеряется ограниченный объём данных с учётом таймаутов и `--speed-max-mb`. Скорость ниже `--min-kb` не попадает в `good` и считается не прошедшей проверку.

TCP ping и speed — разные стадии. Отключение `--no-tcp-ping` пропускает только TCP-префильтр; Xray-проверка остаётся включённой, если не указан `--no-speed`. `--no-speed` не запускает Xray и оставляет `good` пустым. Для режима без сетевых проверок используйте его вместе с `--no-tcp-ping`; если не нужно также GeoIP, добавьте `--no-geoip`.

## GeoIP

GeoIP использует собственный парсер формата protobuf базы `geoip.dat`. Если база существует и успешно разбирается, она переиспользуется; если отсутствует или повреждена, приложение загружает её по `--geoip-url` и атомарно сохраняет в выбранный путь. При `--geoip-db` путь задаётся явно; по умолчанию это `geoip.dat` в каталоге исполняемого файла.

База сопоставляет адреса с кодами стран или специальными тегами. GeoIP применяется к разобранным кандидатам до TCP и скорости; отображаемое имя используется в текстовом выводе и затем передаётся в Clash. `--no-geoip` отключает это сопоставление и переименование, но не влияет на парсинг, TCP, Xray или генерацию Clash.

## Генерация Clash/mihomo

Передайте `--clash`, чтобы записать `clash.yaml` в текущем каталоге, либо укажите путь: `--clash out/proxies.yaml`. В конфиг включаются только прокси из `good` — то есть прошедшие Xray-проверку и порог `--min-kb`. Если `good` пуст, генерация пропускается. Поддерживаются `vless`, `vmess`, `trojan` и `shadowsocks`; прочие протоколы пропускаются и учитываются в отчёте генератора.

Перенос параметров транспорта из Xray в Clash включает:

- TLS-параметры и Reality; значение Xray `realitySettings.password` используется как `reality-opts.public-key`;
- `raw`/`tcp`, `ws`, `grpc`, `xhttp`, `kcp` (для KCP — best effort);
- `httpupgrade` преобразуется в сеть `ws` с опцией `v2ray-http-upgrade`;
- для Trojan имя сервера TLS записывается в `sni`, для VLESS/VMess — в `servername`.

При включённых группах стран конфиг содержит группы стран и GeoIP-псевдостран. Основные группы идут в таком порядке:

1. `🚀 Прокси` — ручной селектор верхнего уровня.
2. `🌍 Страны` — селектор стран и псевдо-стран.
3. `🔓 Заблокированные` — селектор для маршрутов заблокированных сервисов.
4. `🟢 Напрямую` — селектор маршрута с `DIRECT` первым пунктом.
5. Категории `💬 Telegram`, `🤖 AI`, `📺 YouTube`, `🎮 Игры` (если категории включены).
6. `♻️ Fallback`, `⚡ Авто` (`url-test`), `⚖️ Баланс` (`load-balance`).
7. Отдельные группы стран/псевдо-стран в конце.

Группы `⚡ Авто`, `⚖️ Баланс` и `♻️ Fallback` формируются автоматически из прокси. Для известных кодов стран используются флаги; `XX` и неизвестная страна попадают в `🌐 Прочие`. Специальные GeoIP-теги, например `CLOUDFLARE` и `RU-BLOCKED`, получают собственные группы с подходящими значками.

Глобальные секции DNS, sniffer и профиль, а также правила маршрутизации создаются библиотекой `proxy-clash`. Правила для российского трафика (включая `GEOSITE,CATEGORY-BANK-RU`, `GEOSITE,category-ru` и `GEOIP,RU`) направляются в `🟢 Напрямую`; `PROCESS-NAME`-правил нет. При `--clash-no-country` группы стран убираются; при `--clash-no-categories` не добавляются категории, а правила категорий не создаются.

## Архитектура workspace

Корневой `Cargo.toml` одновременно описывает бинарный пакет `proxy-rs` и Cargo workspace с `resolver = "2"`. Единственный отдельный workspace member — библиотека `proxy-clash`.

| Путь | Ответственность |
|---|---|
| `src/main.rs` | Точка входа CLI, обработка Ctrl-C и печать итоговой статистики. |
| `src/pipeline.rs` | Оркестрация этапов, checkpoint/resume, фильтры и формирование выходных файлов. |
| `src/cli.rs` | Аргументы Clap и числовая валидация. |
| `src/sources.rs` | Чтение `sources.json`, объединение URL и прямых ссылок из файла. |
| `src/fetch.rs` | Параллельная загрузка подписок и декодирование Base64-текстов. |
| `src/parse.rs` | Извлечение URI, разбор протоколов, дедупликация и статистика ошибок. |
| `src/outbound.rs` | Построение Xray settings/stream для proxy-ссылок. |
| `src/geoip.rs` | Разбор GeoIP protobuf, загрузка базы и назначение страны. |
| `src/tcp_ping.rs` | DNS-разрешение и параллельные TCP-пробы. |
| `src/speed.rs` | HTTP-замер скорости через SOCKS-клиент и выбор целей теста. |
| `src/check.rs` | Создание HTTP-клиента, подключённого к локальному SOCKS-входу Xray. |
| `src/xray.rs` | Проверка/загрузка Xray, конфиги батчей, управление процессами и фильтрация результатов. |
| `src/output.rs` | Строковое представление прокси и атомарная запись файлов. |
| `proxy-clash/src/lib.rs` | Публичные типы `Source`, `Options`, `Report` и функция `render()`. |
| `proxy-clash/src/convert.rs` | Преобразование Xray proxy/transport-полей в Clash. |
| `proxy-clash/src/groups.rs` | Группы прокси, стран и категорий. |
| `proxy-clash/src/rules.rs` | Глобальные секции и маршрутизационные правила YAML. |
| `build.rs` | Копирование `bin/sources.json` в Cargo build profile. |

`proxy-clash` — библиотека генерации: она получает структурированные источники и возвращает YAML с отчётом, не выполняя сетевой ввод-вывод. Зависимость YAML-сериализации находится только в этом crate.

## Разработка, тесты и CI

### Локальные проверки

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo build --workspace --release
cargo test --workspace
```

Отдельно проверить генератор Clash:

```sh
cargo test -p proxy-clash
```

Тесты workspace используют фикстуры и локальные тестовые серверы. Для документации или обычной проверки кода не нужно запускать реальный сбор прокси из интернета.

Тесты также включают детерминированный fuzz-style корпус повреждённых proxy URI и protobuf GeoIP-данных. Это проверка seeded-регрессий, а не отдельный fuzzing runtime. Синтетические бенчмарки измеряют parse+dedup, GeoIP и Clash-генерацию:

```sh
cargo bench --bench pipeline
```

### Покрытие и mutation testing

В CI на Ubuntu применяются `cargo-llvm-cov` и pinned nightly toolchain. Эквивалентные команды:

```sh
rustup toolchain install nightly-2026-10-26 --component llvm-tools-preview
cargo +nightly-2026-10-26 llvm-cov --workspace --lib --bins --tests --branch --summary-only --ignore-filename-regex '(.cargo/registry|/benches/)' --fail-under-lines 97
cargo install --locked cargo-mutants
CARGO_PROFILE_DEV_DEBUG=0 cargo +stable mutants --workspace --jobs 2 --timeout 120 --minimum-test-timeout 30
```

Coverage job требует не менее 97% line coverage; ветви отображаются в отчёте, но отдельный порог branch coverage в команде не задан. Mutation testing применяет мутации к коду и проверяет, обнаруживают ли их тесты; это длительная проверка.

### GitHub Actions

- `.github/workflows/cross-platform.yml` запускается на `push` и `pull_request`. Матрица Ubuntu, macOS и Windows выполняет Clippy с `-D warnings`, release build и `cargo test --workspace`. Дополнительная Ubuntu job проверяет покрытие и запускает mutation testing.
- `.github/workflows/release.yml` запускается при push тега `v*`. Он собирает архив приложения и документации на Linux, macOS и Windows, прикладывает SHA-256 суммы и создаёт черновик GitHub Release для ручной проверки.
- `.github/workflows/clash.yml` — отдельная автоматизация публикации, а не обычный тестовый CI: по расписанию каждый час (cron в UTC) или вручную она собирает release, загружает и проверяет реальные сетевые источники, GeoIP и Xray, формирует `out/` и force-push-ит сгенерированные файлы в ветку `dist`. В ручном запуске defaults: набор `all`, лимит `25000`; для него требуется сетевой доступ и право записи в репозиторий. Результаты дополнительно загружаются как artifact на 7 дней.

## Типовые ошибки

| Сообщение / симптом | Причина и действия |
|---|---|
| `не найден sources.json` | Укажите существующий файл через `--sources`, URL через `--url` или файл ссылок через `--file`. |
| `битый JSON` / `sources.json должен быть объектом` | Исправьте JSON: корневое значение должно быть объектом наборов, каждый выбранный набор — массивом. |
| `в sources.json нет набора "…"` | Указанный `--set` отсутствует либо не содержит массива; проверьте ключи файла. |
| `не удалось загрузить ни одного источника` | Проверьте URL, доступность сети и `--fetch-timeout`; для теста добавьте прямую ссылку через `--file`. |
| `не найдено ни одного подходящего прокси` | Источники не содержат извлекаемых ссылок поддерживаемого протокола; проверьте формат и поддерживаемые схемы. |
| Ошибка диапазона CLI | Сверьте числовой параметр с таблицей; таймауты должны быть конечными числами, параллелизм и число попыток — положительными. |
| Ошибка загрузки/разбора `geoip.dat` | Проверьте URL и доступ к нему; задайте локальную базу через `--geoip-db` или временно используйте `--no-geoip`. |
| Xray не найден или не запускается | Укажите корректный исполняемый файл через `--core`; при `--no-xray-download` он должен уже существовать и быть пригодным для текущей ОС/архитектуры. |
| После TCP нет живых прокси | Проверьте адреса, DNS, сетевой доступ, `--tcp-timeout`, `--tcp-retries`, `--tcp-max-ms` и `--max-ping`; можно диагностически отключить префильтр через `--no-tcp-ping`. |
| `good.txt` пуст или Clash не создан | Ни один прокси не достиг `--min-kb`, либо включён `--no-speed`. Clash формируется только из непустого `good`. |
| Нет прогресс-бара при перенаправлении вывода | `indicatif` показывает интерактивные бары в TTY; в pipe/файле бары не отображаются. |

При обращении с проблемой приложите команду запуска, версию (`proxy-rs --version`), текст ошибки и сводку этапов. Не публикуйте содержимое частных подписок и конфигураций, если они содержат персональные или чувствительные данные.
